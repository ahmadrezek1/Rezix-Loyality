# Rezix Loyalty v0.6 — Authentication

## Enthalten

- verpflichtende TOTP-2FA für Admin und Manager
- Wiederherstellungscodes für 2FA
- serverseitig registrierte Sessions mit Widerruf
- „Andere Sitzungen abmelden“ für Admin und Manager
- E-Mail-Verifizierung für neue Manager und Friseure
- Passwort vergessen / Einmal-Reset-Link für Manager und Friseur
- Passwortänderung beendet bestehende Sessions
- neue Mitarbeiter-Passwörter werden mit `scrypt` gespeichert; bestehende PBKDF2-Hashes bleiben kompatibel
- Kunde bestätigt die Telefonnummer per 6-stelligem SMS-OTP
- OTP: 10 Minuten gültig, maximal 5 Versuche, begrenzte Sendefrequenz
- Auth-Audit-Ereignisse

## Production Provider

### E-Mail
Rezix nutzt die Resend HTTP API. In Vercel setzen:

- `RESEND_API_KEY`
- `REZIX_EMAIL_FROM=Rezix <noreply@rezix.at>`
- `NEXT_PUBLIC_APP_URL=https://loyalty.rezix.at`

Die Absenderdomain muss bei Resend verifiziert sein (SPF/DKIM nach Provider-Anleitung).

### SMS OTP
Rezix nutzt Twilio SMS. In Vercel setzen:

- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_FROM_NUMBER`

Kundennummern werden im internationalen Format erwartet, z. B. `+43...`.

### Verschlüsselung
`REZIX_DATA_ENCRYPTION_KEY` muss ein eigener langer Zufallswert sein und darf nicht in GitHub gespeichert werden. Er verschlüsselt TOTP-Secrets mit AES-256-GCM.

## Update

```bash
npm install
npm run db:migrate
npm run build
npm run dev
```

Nach der Migration werden bestehende Manager/Friseur-E-Mail-Adressen als bereits verifiziert behandelt, damit bestehende Konten nicht ausgesperrt werden. Neue Konten müssen ihre E-Mail bestätigen.

Beim ersten Admin-/Manager-Login nach v0.6 wird 2FA eingerichtet.

## Lokale Entwicklung

Wenn Resend/Twilio lokal nicht konfiguriert sind, schreibt Rezix E-Mail-Inhalte bzw. OTP-Codes in die Terminal-Ausgabe. Dieser Fallback ist in `NODE_ENV=production` deaktiviert.
